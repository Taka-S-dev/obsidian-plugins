# Terminal Pane

[English](README.md) | 日本語

シェル、GitHub Copilot CLI、自作のターミナルプログラムを Obsidian のペインで動かすプラグイン。Vault のフォルダで起動する。Windows・Obsidian 1.8.7 以降・デスクトップ専用。

表示言語は Obsidian の言語設定に合わせる（日本語なら日本語、それ以外は英語）。

## 何をするか

- 1 つのペインに複数のターミナルをタブで並べる。タブごとに別のプログラムが動く。ペインは右サイドバーに開く。アイコンを中央のエリアへドラッグすれば、ノートの隣に置ける（置いた場所は保たれる）。
- プログラムは本物の疑似端末（ConPTY）で動くので、全画面のプログラムも使える（TUI、エディタ、`copilot`、`nvim` など）。
- タブごとに *プロファイル*（名前付きのコマンドライン）を動かす。最初から PowerShell、コマンド プロンプト、GitHub Copilot CLI がある。自分で追加もできる。
- 開いているタブはワークスペースと一緒に保存され、Obsidian を再起動すると元に戻る（中のプログラムは起動し直し）。

## 前提

- Windows 10 1809 以降（x64）、Obsidian 1.8.7 以降
- PATH に Node.js があること。または設定で Node.js のパスを指定する（Node.js 24 で確認）。ターミナルは別の Node.js プロセスで動く。理由は[仕組み](#仕組み)を参照。

## 使い方

ターミナルの上の帯にタブが並ぶ。

- **+** は既定のプロファイルでタブを開く。**▾** はプロファイルの一覧から選んで開く。
- タブをクリックすると表示が切り替わる。閉じるには **×**、中クリック、または右クリックメニューの **閉じる**（メニューには **再起動** もある）。タブにフォーカスがあるときは、左右の矢印で移動、Enter かスペースで表示、Delete で閉じる。
- 最後のタブを閉じるとペインも閉じる。
- プログラムが終わると、タブが薄く表示され、ターミナルにその旨が出る。そのタブで Enter を押すと起動し直す。

### コマンド

| コマンド | 動作 |
|---|---|
| ターミナルの表示を切り替え | ターミナルにフォーカスがあるときはノートに戻る（ターミナルが右サイドバーにあれば畳む）。それ以外はターミナルのペインを表示する（なければ開く）。VS Code の Ctrl+` と同じ。 |
| 新しいターミナル | 既定のプロファイルでタブを足す。 |
| ターミナルを開く：*プロファイル名* | そのプロファイルのタブがあれば表示し、なければ開く。プロファイルごとにある。 |
| 次の／前のターミナルタブ、ターミナルタブを閉じる | タブの移動と、表示中のタブを閉じる。 |
| 現在のノートのパスをターミナルに入力 | ノートの Vault 内のパスをターミナルに入力する。Copilot CLI で `@` のあとに使うなど。空白や記号を含むパスはダブルクォートで囲む。`$`、`` ` ``、`%`、引用符（PowerShell が引用符として扱う全角の “ ” なども含む）、制御文字を含むパスは入力しない（Enter を押すと、ダブルクォートの中でもシェルが展開したり、引用符がそこで閉じたりするため）。 |
| ターミナル内を検索 | 今のターミナルの上に検索欄を出す。選択中の文字があれば、それで検索を始める。最新の出力から上へ探し、一致をすべて強調する。Enter で前（古い出力）、Shift+Enter で次、Esc で閉じる。 |
| 選択範囲をターミナルに送る | 選択した文字（選択がなければカーソルのある行）を、Enter を押さずにターミナルへ入力する。文字を選択しているときは、エディタの右クリックメニューにも出る。 |

どれも既定のホットキーはない。設定 → ホットキーで割り当てる。

### キー

ターミナルにフォーカスがあるときは、すべてのキーがプログラムに届く。Obsidian が使うキー（Ctrl+P、Ctrl+W、Esc）も含む。モードの切り替えはなく、次の 2 種類のホットキーだけは Obsidian が受け取る。

- このプラグインのコマンドに割り当てたホットキー。「ターミナルの表示を切り替え」を割り当てておけば、押すとノートに戻り、Obsidian のホットキーがすべて使える。もう一度押すとターミナルに戻る。
- 設定の **ターミナルで使う Obsidian のコマンド** に並べたコマンドのホットキー。VS Code の `commandsToSkipShell` と同じ仕組み。既定は空。Obsidian のよく使うキーはターミナルのプログラムも使うため（Ctrl+P と Ctrl+N はシェルの履歴、Ctrl+W は 1 単語削除、全画面のプログラムはさらに多くのキーを使う）。

コピーと貼り付けは Windows Terminal と同じ。

- Ctrl+C は、文字を選択していればコピーする。選択していなければ中断としてプログラムに届く。
- Ctrl+Shift+C はコピー。Ctrl+V と Ctrl+Shift+V は貼り付け。
- 右クリックは、選択していればコピー、していなければ貼り付け。メニューは出ない。Copilot CLI のようにマウスを使うプログラムでは、右クリックはそのプログラムが処理する。Shift を押しながらならターミナル側の動きになる。
- PowerShell やコマンド プロンプトのように、貼り付けをまとめて受け取らないプログラムに改行を含む文字（末尾の改行だけでも）を貼り付けるときは、先に確認する。各行が届いた時点で実行されるため。Claude Code と Copilot CLI は貼り付けをまとめて受け取るので、確認は出ない。どの貼り付けでも、タブと改行以外の制御文字は取り除く。

Shift+Enter は Alt+Enter（ESC のあとに Enter）として送る。画面を描く xterm.js は Shift+Enter を普通の Enter として送るので、プログラムには区別がつかない。Alt+Enter は Claude Code が改行として受け付けるキー。同じ xterm.js を使う VS Code のターミナルで Claude Code の `/terminal-setup` が必要なのも、同じ理由による。PowerShell では Shift+Enter を押しても、行は実行されず何も起きない。設定の **Shift+Enter で改行する** をオフにすると普通の Enter を送る。Claude Code では、どちらでも Ctrl+J で改行できる。

### ノートとの連携

- 出力に Vault 内のファイルを指すパスや `[[ウィキリンク]]` があると、リンクになる。クリックでそのノートを開き、Ctrl+クリックで新しいタブに開く。パスは Vault からの相対でも絶対でもよく、スラッシュの向きも問わない。その場所にファイルがなければ、`[[ ]]` と同じ方法で探すので、`目次.md` のようにファイル名だけでもリンクになる。空白を含むパスは、引用符で囲まれていればリンクになる。ノートがターミナルのタブに開くことはない。
- リンクは、プログラムが付けた色のまま表示する。マウスを乗せると下線が出て、少しすると開くノートのパスと操作を示す。
- ファイルやフォルダをターミナルにドロップすると、そのパスを入力する（必要なら引用符で囲む）。Obsidian からドラッグしたものは Vault からの相対パス、Windows のエクスプローラーからドラッグしたものは絶対パスになる。
- プログラムが入力した内容を処理している間に変更されたノート（アシスタントが書き換えたノートなど）は、**+** の左のボタンに件数が出る。押すと新しい順に一覧が出て、新規・名前の変更・削除の印が付く。クリックすると、最初の変更の前から今までの差分を出す。Ctrl+クリックでノートを新しいタブに開く。Obsidian で入力した直後の保存は数えない。メニューの「一覧を消す」で空にする。
- 変更の差分には **元に戻す** ボタンがあり、確認のあとファイルを戻す。書き換えられたファイルは前の内容に、作られたファイルは削除（Obsidian の削除の設定に従う）、削除されたファイルは作り直し、名前が変わったファイルは元の名前に戻す（リンクも直す）。前の内容を持っておくため、Vault のノート・キャンバス・ベースの本文をメモリに置く（1 ファイル 1 MB、合計 32 MB まで）。それを超えるファイルの変更は、見られるが元に戻せない。
- ほかのノートからリンクされているファイルをプログラムが削除・移動すると、ボタンが警告色になり、一覧の項目に切れたリンクの件数が出る。変更の差分には、リンクが切れたノートが並ぶ。プログラムによる移動は Obsidian には削除と新規作成として届くため、削除したばかりのファイルと同じ内容の新しいファイルは名前の変更として扱う。名前の変更なら **リンクを直す** で、Obsidian で名前を変えたときと同じようにリンクを新しい名前に書き換える。削除なら **元に戻す** でつながる。

### Claude Code・Copilot CLI に開いているノートを伝える

ターミナルで起動した Claude Code と GitHub Copilot CLI は、VS Code につながるのと同じように Obsidian につながり、開いているノートと選択範囲を知る。パスを打たずに「このノート」「選択した行」と頼める。ターミナルにフォーカスがある間は、最後に見ていたノートを伝えたままにする。

- どちらかがファイルの変更の許可を求めると、Obsidian はその変更を差分としてターミナルの隣のタブに出す（消える行と増える行に、前後 3 行を添える。書き換えではなく一部を直した行は、変わった語や文字に色を付ける）。承認か拒否は、タブの **承認**・**拒否** ボタンか、いつもどおりターミナルで選ぶ。決めるとタブは閉じる。タブが開いている間もキーボードはターミナルのまま。
- コマンド **現在のノートを Claude Code・Copilot CLI に添付** で、入力中のプロンプトにノートを @パス として加える（選択していればその行も）。つながっている間は、ノートやエディタの右クリックメニューの **Claude Code・Copilot CLI に添付** でも同じことができる。Copilot CLI は文字を選んでいないと開いているノートを AI に伝えないので、ノートを確実に指すにはこれを使う。
- どちらかがつながっている間は、ターミナルの上の帯にプラグのアイコンと名前が出る。マウスを乗せると、伝えているノートが出る。
- Claude Code 向けには、127.0.0.1 のポートで待ち受け、ランダムな合言葉を書いた `~/.claude/ide/<ポート>.lock` を置く。ターミナルで起動したプログラムには `CLAUDE_CODE_SSE_PORT` でポートを渡すので、Claude Code は `/ide` なしでつながる。
- Copilot CLI 向けには、名前付きパイプで待ち受け、ランダムな合言葉を書いた lock ファイルを `~/.copilot/ide` に置く。Copilot CLI は Vault のフォルダで起動すると自分でつながる。Copilot CLI 側の IDE への自動接続の設定をオフにしている場合はつながらない。
- 合言葉のない接続は断る。lock ファイルはプラグインの終了時に消す。
- VS Code 拡張と Claude Code・Copilot CLI のやり取りに合わせて作っており、公開された仕様ではない。どちらかの更新で動かなくなることがある。設定の **Claude Code と Copilot CLI をつなぐ** で止められる。

### 通知

入力中でないターミナルでプログラムの応答が終わると、タブに点滅するオレンジの点が付き、タブ名もオレンジになる。ペインを置いた Obsidian 自体のタブにも同じ印が付くので、別のノートを開いていても見える。印は、ターミナルのタブに切り替えるか、クリックかキー入力をするまで残る。Obsidian が裏にあるときは、タスクバーのボタンも点滅する。音は鳴らず、ポップアップも出ない。

次のどれかで、応答が終わったとみなす。

- Enter のあとに続いた出力が 3 秒止まった。Copilot CLI などのアシスタントは終わるまでスピナーを動かし、シェルのコマンドは終わるまで出力するので、プログラム側の設定は要らない
- プログラムが端末のベルを鳴らすか、OSC 9 か OSC 777 の通知を送った
- 作業中に出していたタスクバーの進捗表示（OSC 9;4）を、プログラムが消した。Copilot CLI がこれをする

設定の **応答があったタブに印を付ける** をオフにすると止まる。

## プロファイル

プロファイルのコマンドラインは、コマンド プロンプトで打つのと同じく、プログラムのあとに引数を書く。

```text
pwsh.exe -NoLogo
cmd.exe
copilot
"C:\Program Files\My Tool\tool.exe" --flag "a b"
```

- フォルダを含まない名前（`copilot`、`pwsh.exe`）は、PATH から PATHEXT の拡張子を順に試して探す。Vault のフォルダからは探さないので、Vault に置かれたファイルがプログラムに成りすますことはない。
- フォルダを含む相対パスは、Vault のフォルダを基準にする。
- `.cmd` と `.bat`（npm で入れたコマンドなど）は `cmd.exe` 経由で起動する。
- PowerShell のスクリプトは直接は動かない。`pwsh.exe -File script.ps1` と書く。
- プログラムは Vault のフォルダで起動するが、コマンドを Vault のフォルダから探すことはない。プラグインが `NoDefaultCurrentDirectoryInExePath` を設定するので、コマンド プロンプトや `.cmd` ファイル（npm のものは `node` を名前で呼ぶ）が、Vault に置かれた `node.exe` や `git.bat` を実行することはない。コマンド プロンプトで Vault のフォルダにあるプログラムを動かすときは `.\名前` と打つ。

プロファイルごとに「ターミナルを開く」コマンドができるので、プロファイルにホットキーを割り当てられる。名前を変えてもホットキーは保たれる。

## 設定

- **プロファイル**：追加・名前の変更・コマンドの変更・削除。
- **既定のプロファイル**：+、「新しいターミナル」、「ターミナルの表示を切り替え」で使う。
- **ターミナルを開く場所**：ペインがないときに新しく開く場所（右サイドバーか新しいタブ）。既存のペインは置いた場所のまま。
- **文字の大きさ**と**フォント**：フォント名をカンマで区切って指定する。ターミナルのプログラムが表示するアイコンを出すには Nerd Font（JetBrainsMono Nerd Font など）を指定する。空欄なら Obsidian の等幅フォント。
- **Shift+Enter で改行する**：既定はオン。[キー](#キー)を参照。
- **応答があったタブに印を付ける**：既定はオン。[通知](#通知)を参照。
- **Claude Code と Copilot CLI をつなぐ**：既定はオン。[Claude Code・Copilot CLI に開いているノートを伝える](#claude-codecopilot-cli-に開いているノートを伝える)を参照。
- **ターミナルで使う Obsidian のコマンド**：ターミナルにフォーカスがあってもホットキーが効くコマンド。[キー](#キー)を参照。それぞれ今のホットキーを表示する。
- **同梱の ConPTY を使う**：既定はオフ。下記を参照。
- **Node.js**：`node` なら PATH にあるものを使う。別のものを使うときは `node.exe` のフルパスを入力する。

## 仕組み

- 画面は [xterm.js](https://xtermjs.org/) で、WebGL で描画する。WebGL が使えなければ DOM での描画に切り替わる。
- 疑似端末は [node-pty](https://github.com/microsoft/node-pty)。Obsidian の中では動かせない。Windows の node-pty はコンソールの出力を Worker スレッドで読むが、Obsidian のウィンドウでは Node.js の Worker を作れないため。Obsidian の実行ファイルを Node.js として動かすこともできない。そこでタブごとに小さな補助プログラム（`pty-host.js`）を別の Node.js プロセスで起動する。VS Code の pty host と同じ構成。補助プログラムが落ちてもそのタブだけで済み、タブを閉じたときや Obsidian が終了したときに補助プログラムも終わる。
- node-pty はビルド済みのバイナリを Node-API で提供しているので、Obsidian や Node.js を更新しても再ビルドは要らない。
- **同梱の ConPTY**：node-pty には新しい ConPTY（OpenConsole）も同梱されている。Windows 11 build 26300 で測ると、Windows 組み込みの ConPTY より出力が約 2.7 倍遅く、全画面のプログラムの描き換えが途中の状態で見えたので、既定はオフにしている。組み込みの ConPTY で表示が崩れるプログラムがあればオンにする。

## 制約

- ターミナルは Obsidian の起動時の PATH を使う。プログラムを新しく入れたら、プロファイルで使う前に Obsidian を再起動する。
- 再起動後に戻るのはタブの並びだけで、画面の内容は戻らない。
- `.cmd` ファイルから起動したプログラムで Ctrl+C を押すと「バッチ ジョブを終了しますか (Y/N)?」と聞かれることがある。`cmd.exe` の仕様で、どのターミナルでも同じ。
- インストールされるのは Windows x64 用だけ。

## 注意

- プログラムは自分のユーザーの権限で、Vault のフォルダで動く。プロファイルはコマンドラインに書いたとおりに実行される。
- プラグイン自身は他のコンピューターに何も送らない。**Claude Code と Copilot CLI をつなぐ** がオンのときは、この PC の Claude Code と Copilot CLI がつながれるよう 127.0.0.1 と名前付きパイプで待ち受け、開いているノートと選択範囲を伝える。中で動かすプログラムはネットワークを使うことがある。
- プラグインのフォルダには node-pty のネイティブバイナリ（約 2.6 MB）が入る。
- 無保証。利用は自己責任で、利用によって生じた損害について作者は責任を負わない（[LICENSE](../../LICENSE) を参照）。

## 開発

リポジトリの README を参照。`npm test -w terminal-pane`、`npm run build -w terminal-pane`。

ビルドは `src/pty-host.ts` を `main.js` の隣の `pty-host.js` にまとめ、node-pty の実行に必要なファイルをプラグインのフォルダの `node_modules/` に配置する（`package.json` の `plugin` を参照）。動いているターミナルは node-pty のバイナリを開いたままにするので、ビルドは変わっていないファイルを飛ばし、置き換えられなかったファイルがあれば警告する。
